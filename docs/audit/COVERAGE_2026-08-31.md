### From the auth lane (2026-08-31, later session) — found, NOT fixed

- **The pending trap (highest).** `ProtectedRoute.tsx` evaluates
  `approval_status === 'pending'` before the Big-7 profile gate, so a user who
  confirms their email and then abandons `/complete-profile` is bounced to
  `/account-pending` from every route. That screen says "Our team is reviewing
  your credentials", shows "Final admin review — Waiting", and promises "under
  2 hours" — while `complete-signup` auto-approves and **there is no review
  step at all**. It offers no link to `/complete-profile`. The account then sits
  until `cleanup-abandoned-accounts` deletes it at day 30. Prod shows 0 pending
  profiles today, but that is *consistent with* victims having already been
  deleted, not evidence there were none.
- **`/account-pending`'s SLA is unbacked.** `REVIEW_SLA = "under 2 hours"` +
  "Overnight signups clear next morning" are delivered by one deduped admin
  notification (dedupe window 24h — 12× the promise). No cron, no deadline
  column, no escalation, no telemetry measuring `approved_at − created_at`.
- **Brute-force protection is client-side only.** Login's 5-strike lockout lives
  in `safeStorage`. Measured: `localStorage.clear()` + reload resets it and the
  next attempt reaches the network. Correct for its stated threat model (a
  stolen phone driving the UI); whether GoTrue's own rate limit backs it is a
  dashboard setting not readable from this repo.
- **`/reset-password` has no loading state.** `ready` starts false, so the
  "use the reset link from your email" copy paints immediately on a valid link
  before `getSession()`/the hash parse resolves — and if the exchange fails the
  user is left on that wrong message permanently.
- **A successful password change is silent.** `ResetPassword.handleSubmit`
  shows a toast on failure and *nothing* on success — it just navigates to
  `/dashboard` after 800ms. The adjacent comment ("without making the user stare
  at a toast") describes a toast that no longer exists.
- **`/reset-password` is not in the AASA `paths`**, so on iOS a reset link opens
  Safari, not the app. The user then ends up signed in *in Safari* while the app
  still holds the old session. Deliberate or not, it is undocumented.
- **`?redirect=` is written and never spent.** `ProtectedRoute` encodes the

  lands on `/dashboard`. Intentional per the comments, but the plumbing is dead.
- **A dead session presents as "you're still signed in."** `ProtectedRoute`'s

  (which 401s again), and has no sign-out escape.
- **`ban_status === "banned"` is dead everywhere** — no writer produces it, so
  three strings in `AccountBanned` are unreachable.
- `AccountPending` carries ~22 Tailwind color utilities against the

## 4. Method notes worth keeping

Traps that cost real time today; all are now in `CLAUDE.md`:

1. `position: fixed` is **not** viewport-relative here — `backdrop-filter` on every
   frosted surface creates a containing block.
2. A Tailwind variant over a hand-written class compiles to **nothing**; an inline
   `background` shorthand silently overrides `background-image`. **Assert gloss by
   reading the computed style, never the class name.**
3. `parsecheck` does not resolve symbols — a missing import can bind a DOM global.
4. The Supabase CLI is linked to **staging** while `.env` is **prod**.
5. `supabase migration list --linked` therefore reports the wrong project — this is
   where the false "36 pending migrations" figure came from.
6. Service-role bypasses RLS. **Query as a real signed-in user or the gate will
   look like it works when it does not.**
7. PGlite runs migrations locally without Docker; apply 3× to prove replay-safety.
8. A guard that has never failed is not evidence. Reintroduce the defect, watch it
   fail, revert — and include a control proving the guard *reaches* the code.

**Hazard for whoever widens the `jobs` UPDATE policy to the roster:**
`enforce_helper_completion_gates` (20260828011057:219) and
`enforce_helper_jobs_column_whitelist` (:170) both **early-return** when

### 4.2 Fixed this pass

- **`group_job_helpers` had no DELETE policy at all** — so `GroupJobHelpers.tsx`'s
  "Remove Helpr" matched zero rows on every call, forever. Before that file grew
  its `unwrapMutation` guard the failure was silent: the row vanished
  optimistically and the Helpr stayed rostered and still due a payout share.
- **`group_job_helpers` UPDATE was a theft path.** `USING (… OR auth.uid() =
  helper_id)` with no `WITH CHECK` reuses USING as WITH CHECK, so a helper on any
  roster could `SET job_id = '<a stranger's funded group job>'` and
  `process-scheduled-payouts` — which fans out over exactly this table — would
  cut them a Stripe transfer out of that job's escrow. Reproduced in PGlite
  before the fix. Now poster-only, with a trigger freezing `job_id`/`helper_id`
  so even the poster cannot re-point a row.
- **The 5-open-job cap charged recurring posters and then refused them the
  visit.** `enforce_open_job_limit` fires on every INSERT regardless of the new
  row's status, so a poster with 5 open jobs had `charge-recurring-visits`
  succeed on Stripe, get rejected by the trigger, land in its
  "charged-but-not-created" branch and refund — daily, with the poster told
  *"we couldn't charge for your next visit"* (false) and the helper told not to
  turn up. The cap's own metric is `status='open'`, so a non-open insert cannot
  move it; the trigger now returns early for one. Cap strength unchanged
  (proven: a 6th OPEN job is still refused).
- **An under-filled group job could never be released.** `allRosterPaid`
  required `distinctPaid >= helpers_needed`, a threshold a short roster can
  never reach, so the job sat in `payout_pending` and was re-swept hourly with
  every member already paid. Now counted against the actual roster, with a Slack
  page naming the unallocated escrow share so it can be refunded rather than
  resting silently on the platform balance.
- **The release flip stamped one roster member's tier onto everybody's job.**
  `helper_fee_percent` / `platform_fee_amount` are per-helper values on a shared
  row, written by whichever helper settled last — and `helperEarnings.ts` treats
  the frozen percent as the authority on exactly those rows (`shares !== 1`).
  Group jobs no longer stamp them; `payout_transfers` already holds the truth
  per helper.
- **`charge-recurring-visits` dropped two Supabase errors**, one of them on the
  `applications` row its own comment calls load-bearing (the helper's Activity
  tab reads jobs *through* applications). Both now checked; the applications
  failure pages ops, since the visit is funded and cannot be refunded away.
- **`GroupJobHelpers`**: removal now confirms via `BrandConfirmDialog`, notifies
  the removed Helpr (the only lifecycle change in the group flow that told
  nobody), is gated to the staffing window so it matches the new policy, uses a
  44px target instead of a bare 16px icon, and guards the progress bar against
  `NaN%`/`Infinity%` from a null `helpers_needed`.
- **Two flat selected controls, proven flat by computed style.** The weekday
  picker and the One-Time / Repeats / Group segmented control both reported
  `background-image: none` on the pressed cell at all four breakpoints. Both now
  wear `.btn-grad-primary`, re-measured to a real `radial-gradient(...)` at
  320/375/768/1440.
- **The weekday row overlapped itself on every phone.** Measured: **all six
  adjacent pairs overlapping** at 320 and 375, the row escaping its own card by
  22px / 14px. `documentElement.scrollWidth` never moved — the card clips it —
  which is precisely why it shipped. Root cause is the *correct* global
  `button{min-width:44px}` tap-target rule at `index.css:1543`, whose (0,3,1)
  specificity beats `min-w-0`; so the column count adapts instead
  (`grid-cols-3 → 4 → 7`), labels shorten to two letters derived from
  `WEEKDAY_LABELS`, and the full day name moves to `aria-label`. Re-measured
  clean at 320/375/390/430/768/1440.
- **The series preview quoted a total that is structurally below what is
  charged.** `seriesTotalDollars` is `budget × visits` and nothing else, while
  every later visit is billed `budget + poster service fee + sales tax`. Labelled
  ("in labor" / "per visit before fees") rather than restating a fee rate, which
  would be a second source of truth for a number that lives in
  `subscriptionTiers.ts`.

Migration: `20260901030422_group_roster_rls_and_open_job_cap.sql`.
